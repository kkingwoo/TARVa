Transcriptomic Analysis of RNA Variants (TARVa)

Project Overview

TARVa is a workflow which enables analysis of variant calls from raw RNA sequencing data, taking into consideration both depth of read and length of transcript, and scans for all variant call-types in a strand-aware fashion.

The workflow is set up for use with paired-sample raw RNAseq and whole genome sequencing files (fastq) from more than one condition and/or tissue from diploid organisms.

NOTE: Parts or all of the workflow, algorithm(s), and other components of this project are patent pending.

The workflow contains three main pipelines to be run consecutively:
1. Read QC and Data Processing
2. Local Database Build
3. Data Analysis

The project was originally created specifically for analysis of bulk brain tissue samples from Alzheimer’s and cognitively normal aged individuals. The fourth section, Optional Modules outlines analyses included in the manuscript but that may not be applicable to other tissue types or organisms.

Due to resource requirements, it is recommended to use the tool’s --hpc mode whenever possible.

Install

TARVa is distributed as a Python package named tarva.

  • Retrieve the project directory and install the package in place:
git clone https://github.com/kkingwoo/TARVa
cd TARVa
pip install -e .
conda env create -f environment.yml
conda activate tarva
tarva --help

NOTE: If tarva is not in PATH or cannot be installed as indicated above, the tools can still be run in the directory that holds the ‘tarva’ folder with conda environments bio_qc, stringtie, and tarva installed.
Installation of star/2.7.11b, bwa/0.7.17, and R/4.5.1 is also needed. Run commands as:
python -m tarva.cli ...

1. Read QC and Data Processing Pipeline

This pipeline accepts paired-end sequencing FASTQ files and returns RNA-specific variant calls. Reads are sorted by sequencing type and group, then quality-trimmed and aligned. BWA-mem [1] is used for WGS data and STAR [2] for RNA-seq.
The RNA-seq alignments are also assembled with StringTie [3] which allows evaluation of gene expression levels and enables creation of reference files containing both known and novel transcripts.

Data for both sequencing types are run through GATK [4] short-variant discovery pipelines. Two filtered VCF files per individual are created, one for each sequencing type.

Input Files:

  • Reference genome and transcriptome FASTAs
  • Reference genome GTF and GFF3
  • RNA-seq and WGS-seq FASTQ sequencing files for each individual from two different conditions ( recommend n>=30 sample size for each condition)
  • Metadata CSV file. See NOTE below for more information.

NOTE: metadata input

Click to see details about metadata file for input

The modules used in this part require a metadata.csv file. ‘individualID’ field is required. Any variables to be tested in relation to the RNA variants, in addition to the ‘group’ field, should each have their own column. See sample file below, where ‘Age’ is the meta-variable that will be assessed. NOTE: The data analysis pipeline has sufficient power when sample sizes are n=29 or larger.

group individualID WGS RNA wgs_barcode rna_barcode age(mos)
control c1 R281468 R281293 TruSeq3-PE-2.fa TruSeq3-PE-2.fa 2
control c2 R281460 R281291 TruSeq3-PE-2.fa TruSeq3-PE-2.fa 10
control c3 R281467 R281298 TruSeq3-PE-2.fa TruSeq3-PE-2.fa 3
treatment t1 R281462 R281290 TruSeq3-PE-2.fa TruSeq3-PE-2.fa 1
treatment t2 R281465 R281299 TruSeq3-PE-2.fa TruSeq3-PE-2.fa 8
treatment t3 R281469 R281297 TruSeq3-PE-2.fa TruSeq3-PE-2.fa 5

1.) Exactly two distinct groups/conditions/tissues should be present in the ‘group’ column.
2.) individualID is the UUID used for each individual.
3.) Only the unique prefixes from raw fastq file identifiers (columns ‘WGS’ and ‘RNA’) should be the values, ignoring any specific string patterns that identify paired-end reads, (e.g., “_1”,“_2”, “R1”, “R2”).
4.) Barcode/adapter files for use with Trimmomatic are required for QC steps.

Every per-sample step also writes logs/ and, with --array, summary_parts/.

a. Sort input files and prepare reference files

  • Sort and organize input sequencing files if they have not yet been sorted and organized by group/condition, WGS/RNAseq.

Usage: tarva sort-input --help

  • Index and prepare reference files for WGS and RNA-seq alignment tool compatibility. Accepts compressed and uncompressed formats.

Usage: tarva prep-reference --help

b. Read QC

  • Apply FastQC and Trimmomatic to the data, remove low-quality tiles as needed, and return trimmed fastq files.
    This step can be repeated as many times as needed. Read lengths are assessed and metric summaries recorded for each job.

Usage:tarva qc --help

c. Stringtie

  • Step 1: First pass alignment with STAR.

Usage: tarva stringtiepipe align --help

  • Step 2: Assemble transcripts with Stringtie using STAR-aligned reads from Step 1.
    --strandedness is required, see [5] for Stringtie format if data are paired-end.

Usage: tarva stringtiepipe assemble --help

  • Step 3: Identify novel transcripts and merge Stringtie-created reference files with original reference files.
    Output files are used for subsequent data processing steps.

Usage: tarva stringtiepipe novel-transcripts --help

d. WGS

  • Step 4: Align WGS reads using BWA-mem.

Usage: tarva wgseqpipe align --help

  • Step 5: QC alignments with GATK pipeline.

Usage: tarva wgseqpipe preprocess --help

  • Step 6: Create PONs from control group (Optional). Provides the option to create a PONs with the study’s control group for use in Step 7

Usage: tarva wgseqpipe pon --help

  • Step 7: WGS variant calling. Output VCF files.
    Uses Mutect2 with optional –germline-resource and/or –pon panel of normals (PONs).
    IMPORTANT NOTE: If one or either option is used in this step, masking must be done for the matching sites where RNA variants were identified in Step 11. Application of PONs to WGS-only causes ambiguity around origin of variant and may inflate RNA-specific assignment of variant calls.

Usage: tarva wgseqpipe variants --help

e. RNA-seq

  • Step 8: Build index with prep-reference for combined reference created by Stringtie in Step 3.

  • Step 9: Align RNA-seq reads using STAR in 2-pass mode.

Usage: tarva rnaseqpipe align --help

  • Step 10: QC alignments with GATK pipeline.

Usage: tarva rnaseqpipe preprocess --help

  • Step 11: WGS variant calling. Output VCF files.

Usage: tarva rnaseqpipe variants --help

f. Identify RNA-specific variants

  • Step 12: Match RNA and WGS variant call sites for each individual.
    If PON or germline resource were used during WGS --align, those sites should also be masked in RNA to reduce false positives.

Usage: tarva analysispipe rna-unique --help

To reduce the number of times large files are opened and parsed during data analysis, TARVa builds a database for querying.

TARVa Local DB ERD (click to expand)

  • Populate database tables according to the database schema

Usage: tarva dbpipe all --help

3. Data Analysis

This is the pipeline that conducts key analyses and creates figures and tables.
Assesses global-level variant call load between conditions, within genes all variant call-types and across genes per variant call-type.
Filters genes into condition-enriched or shared categories, followed by assessing distributions of unique (site with variant call in only one individual across both conditions)
and common (site with variant call in two or more individuals which can be in a single condition and/or both conditions).
Finally, hones in on significant variant call-types, by type per gene, and highlights sites with significantly different proportions and/or counts.

Run all analyses:

Usage: tarva analysispipe all --help

For single analysis sets:

Usage: tarva analysispipe --help

Python figures run in the tarva environment:

python figures/Fig1_filter_cascade.py --input-dir <results_dir>        
python figures/Fig5_uniqueness_forest.py --input-dir <results_dir>

Figures created by R Markdown need R/4.5.1 with tidyverse and patchwork libraries installed are rendered as:

rmarkdown::render("figures/Fig3_calltype_boxplot.Rmd",
                  params = list(input_dir = "<results_dir>"))
rmarkdown::render("figures/Fig4_tpm_variant_correlation.Rmd",
                  params = list(input_dir = "<results_dir>"))
